# Authoring mgkit skills

## Skill rules

- **Format.** `skills/<name>/SKILL.md` with YAML frontmatter containing exactly `name` (equal to the folder name, kebab-case, at most 64 characters) and `description` (at most 1024 characters, one line, saying what the skill does and when to use it, including trigger phrases). Optional files live next to it: `templates/`, `references/`, `agents/openai.yaml`.
- **Length.** `SKILL.md` is at most 300 lines. Move long templates and reference material to `templates/` or `references/` and tell the agent when to read them.
- **Voice.** Imperative, second person ("Read…", "Ask…"). English only. The conversation with the user follows the user's language; every written artifact (plans, TODOs, roast files, commits) is English.
- **No personal content.** No `/Users/` paths, no names of private projects, no knowledge-base tools, no email addresses. `scripts/check.sh` enforces this.
- **Defaults are defaults.** Write "Save the plan to `plan/…` unless the user's instructions specify another location." Never "always" or "only" for locations, so a user's own CLAUDE.md or AGENTS.md can override.
- **Harness-neutral capability wording.**
  - Subagents: "If you can start subagents, … Otherwise do the same steps yourself."
  - Goal mode: "If this session runs under a goal or long-running mode, … Otherwise keep looping yourself."
  - Never name harness-specific tools (`Task`, `TodoWrite`, `AskUserQuestion`). Describe the action ("ask the user", "track progress").
- **Chaining skills.** Never rely on the harness loading another skill by name. Write: "Read `../review-and-fix/SKILL.md` (relative to this skill's directory) and follow it." Add: "If you cannot resolve that path, search for a file matching `skills/review-and-fix/SKILL.md` inside the mgkit installation."
- **Git side effects.** Skills that commit stage explicit paths and never stage `plan/`. No skill pushes unless the user explicitly asks in the conversation.
- **Attribution.** A skill containing adapted third-party text carries, right after the frontmatter, an HTML comment:

  ```
  <!-- Adapted from <repo URL> (<path>, commit <sha>), MIT License, Copyright (c) <year> <holder>. See THIRD_PARTY_NOTICES.md. -->
  ```

  and the source is listed in `THIRD_PARTY_NOTICES.md` with its full license text.

## HTML plan files generated by mgkit

- One standalone file, inline `<style>`, no JavaScript, no external resources, light and dark via `prefers-color-scheme`.
- Semantic, shallow markup (`h1`–`h3`, `p`, lists, `table`, `pre > code`) so an agent reading the raw source can follow it.
- Code blocks use `<pre><code>` with HTML-escaped content; every plan carries a note telling the reader to decode entities when transcribing code.
- No navigation chrome or library index: title and content only, plus a back link to `INDEX.html` inside big plans.
